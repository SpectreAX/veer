# Veer macOS 原生编辑器第一阶段

日期：2026-10-11。用户已确认：双栏工作台，左侧策略组与规则稿，右侧 AI 指令、出口说明与 Diff；只确认草稿，不控制代理。

## 实施边界

- SwiftUI / AppKit 原生窗口，不使用 WebView。Swift Package 独立放在 `native/macos`，不影响 Android 工程。
- 当前开发机只有 Command Line Tools，Swift 6.4 与 macOS SDK 可用。先编译本地 `.app`，不申请开发者会员，不安装或切换 Xcode，不做公证/商店分发。
- 第一阶段复用 `prototype/ai-editor` 的本机 HTTP 规则引擎与钥匙串接口。应用只发送登记组名、rules 片段和指令；匿名化仍由现有引擎完成。不会自动启动/停止代理、不读取订阅或节点配置。
- 本轮不是独立离线安装包：本机 Node 编辑服务须另行运行。后续打包服务或移植规则引擎应单独评估，不偷偷嵌入 Node 或重复实现 YAML 解析。

## 顺序与门禁

1. 原生协议客户端：类型化请求/响应、仅本机地址、禁止重定向、响应限量、超时与错误。编译和 Swift Testing 验证，再进入 UI。
2. 原生草稿状态：组名登记、规则检查、AI/本地解析、预览、确认、20 次撤销、导出；输入变更后旧候选必须失效，异步结果不可覆盖新草稿。状态测试通过。
3. 双栏窗口：原生字段、中文输入、SecureField、审阅账本和 Diff，明确占位内核校验与未应用。复用现有 Veer 绿色标识，其余采用 macOS 系统语义色/控件。
4. 编译 app、启动测试、输入/预览/确认/撤销/导出、已保存 Key 状态检查。用户文件导出须主动选择路径；不自动导入历史配置，不打印 Key。检查深浅主题、窄窗口和错误恢复。
5. 记录测试与剩余限制，提供本地启动命令。未验证实际代理网络或流媒体解锁。

## 后续阶段

独立应用打包、直接 Security.framework 钥匙串集成、可保存的非敏感工作区、原生规则引擎复用方案、签名与公证按后续需求逐项做；不纳入本轮。
