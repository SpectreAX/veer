# Veer AI 编辑器原型：方向调整与实施计划

日期：2026-10-08

## 产品决定

用户将当前阶段调整为仅包含 AI 编辑能力的 prototype，确认优先支持网站/服务分流；后续仍考虑 AI-powered 完整代理软件。当前选择本机 Web 编辑器作为快速验证载体，现有 Android 工程继续保留。

## 第一版边界

导入文件/粘贴 Mihomo YAML → 解析出口 → 自然语言生成计划 → 引用与规则校验 → 展示 Diff/出口说明 → 用户确认 → 撤销/导出。

支持添加、替换和删除指定类型的规则。网站/服务分流使用示例域名集合，明确其非完整覆盖。遇到不存在的出口、多候选地区、实时测速或运行时切换需求应澄清。第一版不编辑 DNS、策略组结构或 Provider；但必须完整保留它们。模型不输出整份 YAML。

## 实施与门禁

1. **配置编辑核心**：YAML 文档树、受限计划 schema、真实目标引用、规则优先级、未知字段保真。验证复杂 Provider/DNS/锚点样例，重复规则、冲突计划和不存在的目标。
2. **解析入口**：本地确定性解析用于无 Key 演示；OpenAI-compatible AI 入口仅发送出口上下文。验证模型响应、澄清、请求脱敏、超时和 Key 错误。
3. **编辑界面**：导入、手动编辑、指令、修改摘要/文本差异、确认、撤销、导出。验证中文输入、旧草稿失效、取消、错误恢复、桌面/窄屏和主题。
4. **Mihomo 校验**：可配置独立核心路径，执行仅测试配置命令，不启动代理；显示编辑器检查与内核检查的区别。验证成功、失败、超时及资源依赖缺失。
5. **文档与交付**：运行说明、已验证能力和限制、测试记录。

## 后续接回完整代理软件

保持 `core/editor` 与 LLM 入口不依赖 VPN 或运行中 Controller。新增运行时适配器时，应从规则 Provider 刷新、策略组选择等局部操作开始，检测版本和能力后才允许应用。磁盘文件和内核运行态分别管理，配置哈希冲突需重新生成预览；应用失败需回滚并报告结果。

当前 Veer 使用 Mihomo v1.19.29 的本地 mirror。`ReloadRules` 只更新规则表；Android embed mode 禁止 `PUT /configs`。整份配置热加载、现有连接迁移和 Android TUN FD 保持不属于本阶段，不承诺零中断。

## 成功判断

用固定指令与复杂配置做回归，必须没有未经请求的字段变化；模糊指令不能随意选出口。真实用户完成相同分流任务的时间和修改正确率与手工编辑比较。内核解析成功、实际规则命中和服务可访问分别记录，不能相互替代。

实施结果见 `prototype/ai-editor/README.md`。

## 本轮完成记录

上述五项已实现，23 项自动化回归通过，并使用本机 Mihomo 校验器及浏览器完成导入、中文多服务修改、确认、撤销与导出验证。独立界面复核通过；既有 Android 工程保留，未拆除 VPN 功能。

用户填写 Key 后，真实 DeepSeek 模型的 5 个场景测试已通过，详见原型 README。真实代理出口验证仍未完成，需要使用真实配置；AI 返回与配置解析成功不等于分流已在运行中生效。
