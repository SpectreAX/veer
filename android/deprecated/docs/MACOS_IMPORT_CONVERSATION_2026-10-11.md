# macOS：导入优先的对话首页

用户指定以 Codex 为参考，保留原生侧栏、系统深浅色和玻璃操作层；替换首页双栏布局。

## 实施与验收

1. 空态：中央 144pt 液态玻璃加号；底部固定显示「导入配置文件或订阅链接以开始」。未导入不能发送指令。
2. 导入：加号打开原生 sheet；文件选择器或隐藏输入的 HTTPS URL。最大 2 MB UTF-8 YAML；错误可重试，取消/失败不替换草稿。重新导入有未保存修改时先警告。
3. 已导入：首页显示配置名称、对话输入、规则预览；确认后记录修改摘要，继续接收指令。规则和出口管理仍在侧栏。
4. 隐私：完整配置只在本机 Swift/loopback Node 处理；AI 仅接收匿名出口、声明/推断地区和匿名化指令，不接收 rules、节点、Provider URL 或凭证。用户自行输入的其他秘密不能保证自动识别，勿在指令填写密钥。
5. 导出：合并当前 rules 到原始配置副本；非 rules 源码保持不变。默认以 `veer-edited.yaml` 另存；文件导入后保存前明确拒绝原文件及其符号链接/硬链接别名（解析路径与同卷文件身份检查）。URL 导入不自动写回来源。不启用 VPN，不重载代理。

## 有意保留的边界

- URL 须直接返回 Mihomo YAML，不进行第三方订阅转换，不支持 Base64 节点列表；重定向不自动跟随，需最终 HTTPS 地址。
- 地区由出口名称保守推断，歧义标为 UNKNOWN，可手动修改登记地区；不是网络实测。
- 新增规则通过占位出口的本机 Mihomo 检查；不加载真实 Provider。完整原配置仍需真实代理客户端语义与网络检查。
- 完整配置原文（包括其中的秘密）只在本机内存与 loopback 编辑服务中处理；不是对原文进行脱敏后存储。URL 输入在成功导入或关闭 sheet 后清空，不写入偏好。文档和对话仅保存在内存，关闭前需要导出；撤销最多保留 20 项草稿状态。API Key 继续使用系统钥匙串，也可仅供临时会话。
