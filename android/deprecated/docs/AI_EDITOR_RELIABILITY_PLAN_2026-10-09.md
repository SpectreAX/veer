# AI 编辑器可靠性：下一步实施与验证

范围：本机独立规则编辑器，优先网站/服务分流；不接入 VPN、订阅或 Controller，不读取真实节点。沿用 Mihomo v1.19.29 本地 mirror 的占位配置测试。问题属于意图解析与计划校验层，不修改内核。

1. 收紧模型计划边界：只接受协议中的字段和对象形状；未知字段、空操作、混合澄清/操作、伪造出口应拒绝，不能静默忽略。验证正常计划、异常计划及 HTTP 错误路径。
2. 消除本地解析的危险猜测：多出口、互斥动作和带否定的指令应澄清，不因匹配到某个关键词而改错方向。验证明确指令仍可用、整批失败不返回部分修改。
3. 限制 AI 响应实际读取量，响应超限或中途断流时停止解析并给出可重试错误；不显示模型服务原始正文或 Key。验证流式分块响应、超限和断流。
4. 全量回归并以已保存 Key 做真实多服务、缺失/歧义出口、延迟请求与混合操作预览验证。仅使用演示组名与规则，不确认或应用到运行中的代理。记录实际结果，不能用模拟测试代替真实模型结果。

每项完成后验证，再进入下一项。当前没有真实出口/解锁验证，也不承诺任意自然语言意图均能正确理解。

## 完成记录

1. 计划和每个操作均检查对象形状与字段白名单，异常操作按 EditorError 拒绝；完整/独立两个 HTTP 入口均返回 422，不返回部分候选，之后可重新生成。单元与接口回归通过。
2. 本地解析遇到否定、例外、多出口或互斥动作拒绝，明确的多服务指令仍可用。系统提示补充否定、整批澄清与禁止扩展字段。先验证 22 项相关测试，再进行第三项。
3. 实际 AI 响应分块读取上限为 512 KB（包含 JSON 包装），超限立即取消流；保留内容 100000 字符与请求 60 秒限制。断流、无效 JSON、未完整结束的 finish_reason 均拒绝。合法分块和异常响应回归通过。
4. 全量 **40/40 测试通过，0 跳过**；`git diff --check` 通过。使用已保存 Key，真实 DeepSeek `deepseek-chat` 浏览器测试如下，仅操作演示稿，无节点数据。

| 指令场景 | 实际结果 |
| --- | --- |
| Netflix JP＋ChatGPT US＋example.com 直连 | 11 项预览，方向正确，占位 Mihomo 通过 |
| Netflix HK，未登记香港组 | 澄清缺少出口，无候选 |
| 日本或美国，帮我选 | 要求明确唯一出口，无候选 |
| 节点太卡换一个＋Netflix 日本 | 整批澄清，无部分候选；模型说明偏向目标不足，未提供实时测速结果 |
| example.com 不要直连 | 询问替代出口，没有误生成 DIRECT |
| 删除 example.com＋多服务＋屏蔽 | 因未明确删除匹配类型要求澄清，无部分候选 |
