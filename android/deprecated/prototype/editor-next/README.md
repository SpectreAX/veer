# Veer 编辑器下一版交互原型

在 `prototype/opencode-review` 已确认的构图（主对话＋可收起审阅、窄窗口单区域）上，补齐原生 macOS 编辑器已经具备、但旧原型没有表达的状态。沿用其 token，只新增 `warn` 与 `remove` 两个语义色。不修改旧原型、`native/macos` 或 `prototype/ai-editor`。

运行（无需安装依赖）：

```sh
python3 -m http.server 4319 --bind 127.0.0.1 --directory prototype/editor-next
```

打开 http://127.0.0.1:4319/ 。测试：`node --test prototype/editor-next/state.test.mjs`。

## 相比旧原型新增

- **出口地区确认**：导入后列出按组名推断的地区；“未指定地区”的组在开始页与侧栏标出，可就地更正。更正会使未确认候选失效。
- **本地解析 / AI 理解**：分段切换。AI 模式没有 Key 时不能发送，并给出设置入口；AI 对模糊或否定指令返回澄清问题和建议，不生成候选。
- **AI 设置**：演示三种 Key 状态（未设置 / 会话 / 钥匙串）。没有 Key 输入框。
- **校验三态**：通过、失败（候选被阻止，确认按钮禁用）、校验器不可用（可确认，但如实说明未经语义测试）。
- **删除规则与真实 Diff**：基于 LCS 的新增/删除行；大小写不同的已有规则会被替换，不重复。
- **审阅双标签**：“本次修改”与“规则稿”；规则稿显示已确认内容和未导出标记。
- **导出确认**：说明只改 rules、原文件不覆盖，并显示相对上次导出的增删数；导出后清除未导出标记。
- **内置编辑服务状态**：启动中、已停止（草稿保留，可重新启动）。

演示场景菜单：正常、校验失败、校验器不可用、请求失败、编辑服务不可用；“长名称示例”在下次导入时生效。

## 边界

全部为合成数据。CSP `connect-src 'none'`：不读取文件、不下载订阅、不请求 AI、不访问钥匙串。导出文件带注释说明是合成副本，不是可用代理配置。CSS 玻璃只是近似效果，不代表 macOS 原生材质。

## 已验证

- 状态测试 9/9 通过。
- 在内置浏览器中测试 1440×900 浅色和深色、1080×760（审阅替换对话区域）、390×844 长名称（无横向溢出），控制台无错误。
- 走通的流程：导入、更正地区、生成、审阅、确认、规则稿、AI 澄清、校验失败阻止确认、服务停止横幅、导出。

未验证：屏幕阅读器朗读顺序、强制颜色模式、键盘逐项遍历。
