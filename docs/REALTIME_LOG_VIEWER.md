# Veer 实时日志查看器设计

日期：2026-07-30  
状态：已完成并通过模拟器/真机核心链路验证

## 目标

把首页内嵌的诊断文本升级为独立日志页面，使普通用户能判断启动、网络和节点故障，
同时继续保证订阅地址、API Key、Token 和密码不会出现在显示、剪贴板或导出文件中。

## 已有基础

- UI 与 `:veercore` 进程分别持有 500 条内存环；
- Veercore 通过同 UID ContentProvider 最多返回 200 条、每条最多 800 字符；
- 日志进入 Logcat、磁盘、SharedFlow 和 IPC 前统一执行 `VeerLog.redact`；
- 磁盘日志保留三天；
- 首页仅在展开时每秒拉取 Veercore 日志。

## 数据模型

日志查看器把文本规范化为：

```text
时间 · 来源(UI/Core) · 级别(D/I/W/E) · 分类 · 消息
```

Veercore IPC 格式增加级别字母；解析器继续兼容旧的无级别行，并标记为
`UNKNOWN`，避免升级安装后短期日志无法展示。

## 交互

- 来源筛选：全部、UI、Veercore；
- 级别筛选：全部、Debug、Info、Warn、Error；
- 关键字搜索：匹配分类与消息，忽略大小写；
- 实时/暂停：暂停后保持当前快照，不继续触发 IPC；
- 刷新：显式拉取一次；
- 复制：只复制当前筛选结果；
- 导出：通过 Android SAF `CreateDocument` 由用户选择位置；
- 新日志显示在列表顶部，避免强制抢夺用户正在阅读的位置。

## 生命周期与性能

- 页面进入 `RESUMED` 后每秒刷新一次；
- 页面进入后台、销毁或用户暂停时停止周期刷新；
- 单次最多合并 500 条 UI 日志和 200 条 Core 日志；
- 过滤在内存中完成，不为每次键入发起 Binder 调用；
- 不建立新的跨进程长连接或无界日志队列。

## 安全

- 所有来源在存储前已经脱敏；
- 复制和导出前再次调用集中脱敏器作为纵深防御；
- 文件名不包含配置、节点、设备或账户信息；
- 导出使用用户主动选择的 URI，不申请广泛存储权限；
- 页面不显示完整线程栈以外的配置文件内容。

## 验收

1. 解析器覆盖新旧 IPC 格式、四个级别和格式错误行。
2. 来源、级别、关键字组合筛选结果正确。
3. 暂停后仓库不再周期刷新，恢复后立即获得新快照。
4. Compose 页面可展开筛选、显示日志和执行操作。
5. 复制与导出内容不包含测试 API Key、Bearer、Token 或 URL。
6. 单元测试、Lint、Debug/Release/AndroidTest 构建通过。
7. 真机运行时可同时看到 UI 与 Veercore 日志，VPN/Controller/公网仍健康。

## 实施结果

- 新增独立 `LogsActivity`，首页可直接进入，不再把诊断信息挤在连接操作区域。
- `LogViewerViewModel` 只在页面处于前台且未暂停时刷新；筛选和搜索只处理当前
  内存快照，不为输入框的每次变化发起跨进程请求。
- `LogViewerRepository` 合并 UI 与 Veercore 的有界日志环，并在复制、导出前
  再次统一脱敏。
- 日志模型兼容带级别的新格式和升级前的旧格式；无法解析的内容安全降级为
  `UNKNOWN`，不会导致页面崩溃。
- 导出使用系统 `CreateDocument`，不申请存储权限；复制和导出只包含当前筛选结果。
- Debug 验收接口可导出查看器当前快照与统计，供锁屏或无人值守真机门禁使用。
