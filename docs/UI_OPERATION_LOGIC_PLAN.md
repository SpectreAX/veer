# Veer UI 操作逻辑优化计划

更新时间：2026-07-28

状态：P0 与快速重连优化已完成并通过 Android 16 arm64 模拟器验证；P1 待后续实施。

## 1. 目标

本轮不改变 Veercore、VPN 生命周期和 AI 事务语义，只优化用户从“打开应用”到
“导入配置、连接、执行 AI 指令、查看结果”的操作路径。

设计原则：

1. 一个状态只突出一个主操作，避免同时显示互斥按钮。
2. 按当前缺失条件给出下一步，而不是只禁用控件。
3. 高频操作默认可见，密钥和运行日志等低频内容按需展开。
4. 成功、失败和处理中状态在操作附近反馈，不要求用户从日志中判断结果。
5. 所有异步操作防重复点击；状态来源继续使用 `AppStateRepository`。
6. 不使用伪成功、假节点或仅在 UI 中变化的状态。

## 2. 当前操作问题

### 2.1 首页

- “Start VPN”和“Stop VPN”同时占据主操作区，用户需要先理解状态再选择按钮。
- 没有活动配置时只显示警告和禁用的启动按钮，正确下一步“导入配置”不够突出。
- Profiles、AI Rules、Nodes 与启动按钮视觉权重接近，主次不清。
- API Key 编辑器永久占据首页；密钥已保存后仍重复展示低频设置。
- AI 成功或失败主要写入底部日志，输入区附近没有明确结果。
- 运行日志默认占据 320dp，高频操作被推到长页面底部。
- 中英文混用，增加扫描和理解成本。

### 2.2 配置页

- 订阅 URL、文件选择和大段 YAML 输入同时展开，首次用户难以判断应使用哪一种。
- 首次成功导入后仍需滚动到配置卡片并再次点击 Activate。
- 成功状态没有直接提示“现在可以返回并连接”。
- 页面操作反馈使用英文，和首页中文状态不一致。

### 2.3 节点与规则

- 未连接时仍允许进入依赖控制器的操作页面，错误提示晚于用户动作。
- 页面采用独立 Activity，首页需要明确说明哪些操作要求 VPN 已连接。

## 3. 目标操作流程

### 3.1 首次使用

```text
打开 Veer
  → 主按钮显示“导入配置”
  → 默认使用订阅链接导入
  → 首个配置自动激活
  → 返回首页，主按钮显示“启动 VPN”
  → 授权后连接
  → 首页显示出口、节点和连通性
```

### 3.2 日常连接

```text
Stopped  → “启动 VPN”
Starting → “正在启动…”（不可重复点击）
Running  → “断开 VPN”
Stopping → “正在停止…”（不可重复点击）
Error    → “清理并停止”
```

运行中同时提供次级操作“快速重连”。它由 VPN 服务在同一实例内完成安全关闭与立即启动，
不等待 Android 延迟触发的服务销毁回调；主操作仍保持“断开 VPN”，避免改变显式断开语义。

### 3.3 AI 指令

```text
未保存 Key → 输入区显示缺失条件，并展开 AI 设置入口
VPN 未连接 → 保留输入内容，按钮提示“连接后可执行”
可执行      → “执行指令”
执行中      → 锁定重复提交并显示进度
成功/失败   → 在输入区下方显示最近结果；详细技术日志按需展开
```

## 4. 分阶段实施

### P0：本轮实施

1. 首页将 Start/Stop 合并为单一上下文主按钮。
2. 无活动配置时主按钮直接进入配置导入页。
3. 首页快捷入口统一中文，并依据运行状态限制节点操作。
4. API Key 设置默认折叠；无 Key 时自动展开并说明用途。
5. AI 输入区增加前置条件和最近一次执行结果。
6. 运行日志默认折叠，用户主动点击后才展开。
7. 首次成功导入配置后自动激活，移除不必要的第二次操作。
8. 配置页主要操作与提示统一中文。

### P1：后续实施

1. 配置导入改为“订阅链接 / 本地文件 / 粘贴 YAML”三种互斥方式。
2. 将 Profiles、Rules、Nodes 收敛到统一的应用内导航，减少 Activity 跳转。
3. 增加最近 AI 操作历史、撤销入口和规则变更预览。
4. 增加可访问性语义、动态字号、TalkBack 和横屏验证。

## 5. 状态与操作规则

| 条件 | 主按钮 | AI 提交 | 节点页 |
|---|---|---|---|
| 无活动配置 | 导入配置 | 禁止，并提示先导入 | 禁止 |
| Stopped | 启动 VPN | 禁止，保留输入 | 禁止 |
| Starting | 正在启动 | 禁止重复提交 | 禁止 |
| Running | 断开 VPN | Key 存在时允许 | 允许 |
| Stopping | 正在停止 | 禁止重复提交 | 禁止 |
| Error | 清理并停止 | 禁止 | 禁止 |

## 6. 验收标准

### 自动化

- 单元测试覆盖主按钮状态映射和 AI 可执行条件。
- `testDebugUnitTest`、`assembleDebug`、`assembleRelease`、`lintDebug` 全部通过。
- `git diff --check` 通过。

### Android 16 模拟器

1. 删除活动配置状态下，首页只突出“导入配置”，点击进入配置页。
2. 首次导入后配置自动激活，返回首页无需再点击 Activate。
3. Stopped、Starting、Running、Stopping、Error 分别显示正确的唯一主操作。
4. 已保存 Key 时首页默认不展示密钥输入框；可手动展开、覆盖或清除。
5. VPN 未连接时 AI prompt 内容不会因按钮禁用或状态刷新丢失。
6. AI 操作只能提交一次，成功与失败均在输入区附近可见。
7. 日志默认不占据首页空间，展开后仍保留最多 200 行限制。
8. 最终 VPN 为 `Running`、控制器可用、互联网实际可用，经 mixed-port 请求
   `https://www.gstatic.com/generate_204` 返回 HTTP 204。

## 7. 非目标

- 本轮不改变 JNI 调用、超时、自动恢复和 VPN teardown。
- 本轮不改变 AI system instruction、规则事务和节点选择算法。
- 本轮不删除现有详细日志，只改变默认展示方式。
- 本轮不把 API Key 写入构建配置或非加密偏好。

## 8. P0 实施与验证结果

实现：

- 新增纯状态操作模型，将活动配置与 `EngineState` 映射为唯一主按钮：
  `导入配置 / 启动 VPN / 正在启动 / 断开 VPN / 正在停止 / 清理并停止`。
- 节点入口只在 VPN `Running` 时允许点击；配置和 AI 规则保持随时可检查。
- API Key 已保存时默认折叠，缺失时自动展开；保存后自动收起，清除后重新展开。
- AI 输入区显示明确的缺失条件和最近一次执行结果；prompt 在连接状态变化时保留。
- 运行日志默认折叠，展开后继续使用最多 200 行的内存上限。
- 首次成功导入的配置自动激活；已有活动配置时，新导入不会造成运行配置切换。
- 通知权限与 VPN 启动改为顺序流程，避免两个系统授权窗口重叠。
- 首页和配置页的主要动作与状态提示统一为中文。

自动化结果：

```text
./gradlew :app:testDebugUnitTest :app:assembleDebug \
  :app:assembleRelease :app:bundleRelease :app:lintDebug
git diff --check
```

全部通过。新增测试覆盖无配置引导，以及 Stopped、Starting、Running、Stopping、
Error 的主按钮映射和 AI 前置条件。

模拟器结果：

1. 清除应用数据后，首页唯一主按钮为“导入配置”，AI 区明确提示先导入。
2. 真实订阅首次导入成功后自动显示“当前使用”，并提示可返回首页启动 VPN。
3. 返回首页后主按钮由“导入配置”变为“启动 VPN”；运行后变为“断开 VPN”。
4. 通知授权完成后才继续 VPN 启动流程，未出现授权窗口叠加。
5. VPN 到达“运行中”，Mihomo 控制器可用，互联网实际可用。
6. Key 编辑器和运行日志均完成展开/收起验证；Key 仅以加密字段持久化，无明文。
7. 控制器返回 Mihomo `1.10.0`，mixed-port 真实代理请求返回 HTTP 204。

## 9. 节点一键测速扩展

状态：已完成并通过真实订阅验证。

操作逻辑：

- “节点与策略组”页顶部提供“一键测速”，对页面中的全部真实叶子节点执行检测。
- 同一节点即使被多个策略组引用也只发起一次请求，结果同步回填到所有引用位置。
- 最多同时检测 4 个节点，单节点超时为 3 秒，避免大量并发请求拖慢代理核心。
- 测速过程中显示完成数、总数、可用数、失败数和进度条。
- 批量测速期间锁定刷新、切换、自动选低延迟和单节点测速，避免并发操作覆盖状态。
- VPN 停止时自动取消批量任务并清理进度。
- 完成后保留逐节点延迟/不可用状态，并显示汇总结果；不会自动改变当前节点。

验证结果：

- 单元测试覆盖跨策略组去重、同名节点多处回填、失败状态和进度汇总。
- 当前真实订阅共识别 31 个唯一可测速节点；运行时进度成功显示
  `8/31 · 可用 5 · 失败 3`。

## 10. 快速重连扩展

状态：已完成。

实现：

- 首页在 `Running` 状态显示次级操作“快速重连”，一次点击完成关闭与恢复，不再要求用户
  先点“断开 VPN”、等待状态切换后再点“启动 VPN”。
- `VeerVpnService` 新增同实例串行重连事务，状态按
  `Running → Stopping → Starting → Running` 变化。
- 重连继续复用 `engineMutex`、`tearDownCore()` 和 `bootCore()`；原有 JNI 5 秒停止超时、
  外层 4 秒互斥等待和不可恢复错误保护均未缩短或绕过。
- 重连期间不发布短暂 `Stopped`，避免主按钮在中间帧变为可点击的“启动 VPN”。
- 重复重连、显式停止、配置切换之间通过原子门控和现有互斥锁避免重入。

基线测量：

- 普通停止：`Veercore.stop()` 1–28ms，完整 teardown 6–63ms。
- 分开的冷启动：约 544ms 到达 `Running`。
- 在服务销毁前复用实例：从停止命令到重新 `Running` 约 355ms。

验证结果：

- 新增仪器化生命周期测试通过，确认没有中间 `Stopped` 帧。
- 首轮 5 次真实重连为 186–218ms；扩展 10 次为 175–907ms。
- 扩展 10 次均在 442–1256ms 内通过代理返回 HTTP 204，控制器持续可用。
- 全程服务实例数为 1，最终状态为 `Running`，Android VPN owner 为 `com.yamax.veer`。
- 补充验证启动竞态：`Starting → Stop → 立即 Start` 时，第二次启动先排队，旧运行时
  安全释放后只启动一次；测试最终恢复 `Running`，无 `Error`、无重复 native runtime。
- 修复一次真实误停：此前第二次启动成功约 57 秒后，出口自动恢复因候选快照暂时为空而
  将 VPN 主动关闭。现在候选耗尽仅保留降级状态并继续探测；真实运行观察 80 秒跨过原
  误停窗口，始终 `Running`、单服务实例、无 crash buffer。
- 完整检测结果为 10 个可用、21 个超时或失败；可用节点显示实际毫秒值，失败节点
  显示“不可用”。
- 页面顶部操作重新排版，标题不再因“刷新/一键测速”按钮被压缩换行。
- Debug/Release/AAB/Lint 与格式检查全部通过。

## 11. 启动进度扩展

状态：已完成。

交互逻辑：

- 首页只在 `EngineState.Starting` 期间展示启动进度面板，进入 `Running`、`Error`、
  `Stopping` 或 `Stopped` 后自动收起。
- 面板同时展示当前阶段、步骤数、百分比和确定性进度条；启动按钮在此期间继续禁用，
  防止重复提交。
- 五个用户可理解的真实阶段依次为：准备代理配置、检查运行数据、校验代理配置、
  创建 VPN 通道、启动 Mihomo。
- 百分比由阶段里程碑映射，不使用计时器猜测启动耗时；耗时较长时，界面会稳定停留在
  正在执行的真实阶段。

状态与架构：

- `VeerVpnService` 是启动阶段的唯一写入者，在配置准备、GeoDB、配置校验、TUN 建立和
  原生运行时启动边界发布 `StartupStage`。
- `AppStateRepository` 将阶段与 `EngineState` 一起聚合到 `RuntimeState`；UI 仍只观察
  单一 `AppState`，不会直接驱动 Mihomo 生命周期。
- 离开 `Starting` 时阶段立即重置为 `IDLE`，避免下次启动闪现上一次的旧进度。

验证结果：

- 单元测试确认所有可见阶段的进度严格递增、范围合法并具有用户文案。
- 原生故障注入将 `ApplyConfig` 阻塞时，服务稳定发布
  `STARTING_RUNTIME`；释放后到达 `Running` 并清空启动进度。
- Android 16 Compose 仪器化测试确认首页显示进度面板、进度条、`50%` 和
  `步骤 3/5 · 校验代理配置`。
- 为支持 Android 16 UI 测试，AndroidX Test 升级至 JUnit 1.3.0 / Espresso 3.7.0。

## 12. AI 规则流向可读性

状态：已完成。

- 规则卡片主标题使用“匹配对象 → 流量出口”，例如 `Netflix → 香港（HK）`，不再只以
  `netflix` 作为标题。
- 卡片增加高对比度“流量出口方向”区域，直接展示实际绑定的策略组或具体节点名称。
- GEOSITE 服务名转换为用户熟悉的产品名，同时在次要文字保留原始匹配信息，例如
  `服务流量 · GEOSITE/netflix`，方便核对规则实现。
- `DIRECT` 与 `REJECT` 分别展示为“直连（不经过代理）”和“拦截”；常见纯地区代码会
  展开为香港、日本、美国、新加坡或台湾。
- “改绑策略”操作统一改名为“更改出口”，选择窗口标题改为“选择流量出口”。
