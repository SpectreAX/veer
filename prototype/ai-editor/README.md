# Veer AI Editor Prototype

当前阶段聚焦 AI 配置编辑，后续仍计划开发完整 AI-powered 代理软件。

## 默认：独立规则模式（2026-10-08）

首页默认不导入完整配置、不连接 Controller、不下载订阅。手工登记实际策略组名称与声明地区，编辑仅含 `rules` 的 YAML 片段；名称及规则稿只发送到本机编辑器。AI 使用匿名编号与地区，指令中登记组名会替换成匿名标签，完整规则稿不进入 AI 请求。本地恢复真实组名。不要在指令中自行输入密码；这不是任意自由文本的通用脱敏器。API Key 仍会发送给你选择的服务用于认证。

确认、撤销、检查和导出均只作用于规则稿。导出的 `veer-rules-fragment.yaml` **不是完整配置或通用覆写模块**；请按客户端支持的方式将规则合并到原规则之前，并由客户端验证组名、规则顺序与实际出口。占位策略组内核检查只验证片段语法/结构，不证明真实组存在或网络可达。不接受 MATCH、RULE-SET 等未实现规则类型；不接收节点属性、其他顶级字段或 YAML 引用。

完整配置模式保留在 `/advanced`，有明确本地读取提醒。两个页面不共享规则稿或历史；它们可以使用同一 API 地址的系统钥匙串 Key。

## API Key 持久化

在 AI 服务设置填写 Key，点击“保存到钥匙串”。macOS 使用系统钥匙串加密保存，按规范化 API 基础地址隔离。页面刷新和本机服务重启后，只恢复“已保存”状态，不将秘密回传到输入框；模型调用由服务端读取 Key。更换地址立即取消旧 Key 状态，未保存的输入仍可临时使用。需要移除时点击“删除已保存 Key”。API 地址和模型本身暂不持久保存，非默认地址再次打开时需重新选择。

不使用 localStorage、明文配置文件或命令行参数传递秘密。钥匙串锁定或拒绝权限时明确报错，不回退明文存储。目前仅支持 macOS；其他系统仍可使用会话 Key。系统钥匙串不是对已获得本机用户权限的恶意程序的绝对防护，请保持本机账号安全。

验证：34/34 测试通过。使用独立、非真实测试值完成系统钥匙串保存/读取/清理，浏览器保存后输入清空，刷新后按地址恢复状态且未回传秘密；地址切换、陈旧响应、保存失败重试、删除和 HTTP 来源门禁均有回归。尝试迁移旧页密码框时浏览器返回脱敏占位值，该无效记录已清理并新增占位值拒绝检查。用户需在新版页面重新填写真实 Key 并保存一次；本轮未验证真实已保存 Key 的云端调用。

## 运行

需要 Node.js 22+。在本目录执行：

```sh
npm ci
npm run build:validator
npm start
```

`build:validator` 需要 Go，使用仓库内 `go_core/third_party/mihomo` 的修改版 mirror 构建本机校验器，产物只写入已忽略的 `.cache/`。它不是官方发布二进制，也不启动代理。Veer 的 `go_core/go.mod` 声明 Mihomo v1.19.29 并 replace 到该 mirror；编译产物用 `veer-editor-local-mirror` 标识，避免将默认 linker 版本误报为真实版本。

访问 <http://127.0.0.1:4317>。服务只绑定本机；`VEER_EDITOR_PORT` 可改变端口。也可用 `MIHOMO_BIN=/绝对路径/mihomo npm start` 指定已有的可信核心，无需自行构建。未配置校验器时仍可编辑/导出，但界面会明确显示“尚未通过内核语义校验”。

## 高级模式使用（/advanced）

1. 导入 `.yaml/.yml/.txt` 或粘贴配置；演示配置的节点不可用于真实代理。
2. 本地解析无需 Key，适合 `Netflix 走日本，ChatGPT 走美国`、`example.com 直连`、`example.com 屏蔽`、`删除 example.com 规则`。地区存在多个候选时，插入完整出口名称。
3. 更自由的表达选择 **AI 理解 · API**，填写 OpenAI-compatible 基础地址、模型和 Key。默认设置为 DeepSeek，基础地址不要包含 `/chat/completions`；其他兼容服务可填写带 `/v1` 的基础地址。Key 可保存到 macOS 钥匙串，或仅会话使用。
4. 查看逐条匹配项、完整出口名称和 YAML 差异。候选配置内核校验失败时不能确认。修改会放在现有规则之前，同类型/同匹配值的旧规则会替换而非重复追加。
5. 确认只更新本页编辑稿，可撤销最近 20 次编辑并导出。代理客户端导入和真实出口测试由用户后续进行。手工编辑后请使用“检查配置”；导出本身只保证编辑器结构检查通过。

## 边界与隐私

- 支持 `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`IP-CIDR`、`IP-CIDR6`、`GEOSITE`、`GEOIP` 的添加、替换和删除。第一版本地解析主要支持 DOMAIN-SUFFIX；其他类型可通过 AI 生成结构化计划。
- Netflix、ChatGPT、YouTube、Telegram 使用内置的常见域名目录，目录并非完整服务规则集，不保证解锁。用户明确指定单个域名时只修改该域名。
- 地区推断来自节点/组名称，不是地理或网络实测。需要测速、运行时选择、DNS/Provider 结构修改的要求会被提示澄清。
- 原配置限制为 2 MB。AI 目标上下文限制为 2500 个，单次计划最多 32 项。目标名称含逗号/换行的配置无法安全引用，会明确拒绝。
- AI 请求只包含指令、出口名称/类型和内置目录；不发送整份 YAML、节点服务器或节点密码。出口名称仍会发给所选 AI 服务。
- 配置保存在页面内存中，API 请求在本地处理，不写入配置文件或日志。刷新/关闭页面会清空编辑稿和未保存 Key；已保存 Key 保留在系统钥匙串。请及时导出编辑稿。
- 原型只替换 `rules` 的源码范围，规则以外文本逐字保留；结构检查同时验证未知字段、Provider、DNS 和锚点没有未经请求的语义变化。规则本身的格式可能规范化。
- Mihomo 校验使用独立临时目录、`-t -f -` 和 20 秒时限，结束后删除临时目录。依赖外部 GEO/Provider/相对资源的配置可能需要额外资源；校验失败会显示提示，不会修改运行中的代理。
- 首版没有 VPN、Controller 连接、订阅下载或热应用功能。

## 架构与后续复用

2026-10-09 可靠性补强：模型计划采用字段白名单，异常/部分操作整批拒绝；本地解析对否定、例外和多出口表达提示澄清。AI 响应按分块限量读取（512 KB），超限、断流或输出未完整结束不生成候选。40/40 自动化测试通过；真实模型验证 7 个场景，含 11 项多服务/直连和 12 项删除/多服务/屏蔽预览，两者通过占位内核测试。删除规则可能需要明确匹配类型；模型不读取规则稿。详细结果见 `docs/AI_EDITOR_RELIABILITY_PLAN_2026-10-09.md`，未应用到代理。

`core/editor.mjs` 负责配置、真实出口、计划校验和确定性修改；`core/llm.mjs` 负责模型交互；`core/validator.mjs` 负责仅测试配置；`server.mjs` 是本机 HTTP 适配层；`public/` 是编辑/审阅界面。

后续运行时适配器消费已校验的计划，分别实现 Provider 刷新、策略组选择和支持范围内的局部规则应用。文件草稿与运行中状态分开记录，确认不能冒充“已生效”。Android 可复用计划协议与测试样例，移植确定性编辑逻辑；此版本没有直接依赖 Kotlin/Android 服务。
