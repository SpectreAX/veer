## 改变机制的依据

旧方案同时绘制窄布局的活页面和宽布局的旧图。移动过的文字在淡出期间会出现在两个位置；增加模糊、延迟或调整持续时间仍保留这两套位置。关闭方向还只截取原窄页面，面板腾出的右侧区域从第一帧就露出新布局，截图与实时内容之间有接缝。流量等实时值也会从冻结图跳回当前值。[Issue 分析](https://github.com/SpectreAX/veer/issues/15)

连接页还有可量到的二次变化。本次以 Computer Use 点击基线隔离样例的 Agent 按钮，采集只读布局日志。打开时，左侧表宽从 880 点直接变成 499 点，约 127 ms 后隐藏列集合才切换为 chain/duration/rule。关闭时表宽直接回到 880 点，约 128 ms 后恢复列。页面排版、延迟适配的表格列与 220 ms 面板滑动分属不同时间点。Computer Use 返回的稳定截图能确认列集切换；中间的双层内容由用户截图及下方保留原帧确认。此次 Computer Use 没有采到完整的高帧率过渡。

## A 方案的实现边界

1. 在现有详情区上方保留右侧 ZStack 面板，正文维持面板关闭时的宽度。移除因面板开关改变的 `TrailingInsetLayout`、页面快照、模糊淡出、提前截图回调和中间显示状态，保持单个面板可见状态。
2. 面板沿右缘移动，使用不透明背景和符合现有设计的分隔边缘。拖动面板宽度只改变覆盖范围。面板外露出的正文、表头、节点和卡片保持原来的坐标、列集及字号。
3. 同时审查页面里依赖 `store.agentPanel` 的分支。概览目前会移除提问栏，工具栏可能替换内容；会改变正文几何的分支须在样例中明确处理，保证面板开关期间可见正文稳定。
4. 用窗口按钮和 ⌥⌘I 测试开、关、快速反向；验证被面板盖住的正文无法误点，键盘焦点可进出面板，关闭后正文原位置能继续操作。向用户展示遮挡的内容与恢复方式，保留“打开 Agent 页面”的入口。
5. `PageSnapshot.swift` 与 `PanelMotionTests` 在工作区可能已被其他开发过程删除。应根据最终调用关系清理，并补充有意义的覆盖范围、命中与状态测试。左导航边栏动画属于另一个机制，其观察状态问题按 issue 的独立观察处理。

主要入口为 `MainView.swift`、`SplitDetailViewport.swift`、`ProxyStore.swift`、`OverviewView.swift`、`Agent/AgentPanel.swift`。本次仅文档和隔离样例分析，产品工作区源码的现有修改来自并行开发。

## B 方案的使用条件

若样例验收确认必须让左侧正文始终完整可见，再评估 issue 的 B 方案：把 Agent 面板作为真实 `NSSplitView` 第三列，以 AppKit 分隔条驱动真实宽度。先测代表性代理与连接数据的每帧布局开销，目标为约 16 ms；重排持续超预算时停止该实验并记录结果。历史 SwiftUI 宽度步进曾花费 30–70 ms/帧，现有左边栏驱动的表现不能直接证明第三列也达标。示例数据阶段先比较机制，真实性能验收遵守当前机器的系统代理、TUN 和真实应用测试限制。[Issue 的两个方向及性能门槛](https://github.com/SpectreAX/veer/issues/15)
