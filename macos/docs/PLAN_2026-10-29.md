# Veer for macOS：项目计划（2026-10-29）

Veer 是用 AI 决定流量走向的代理工具，等于 Veer AI Editor 加上完整的代理功能：导入订阅、运行 Mihomo、切换节点、系统代理和 TUN。用户用一句话改分流（“Netflix 走日本”），改动审阅后立即在运行中的内核生效。

## 已确定的决定

| 问题 | 决定 | 影响 |
|---|---|---|
| 发布方式 | 官网直接下载：Developer ID 签名并公证，不上 Mac App Store | 不用 Network Extension；TUN 通过一次授权的后台服务获得权限 |
| 和 Veer AI Editor 的关系 | 共用核心库 | Veer 通过 Swift 包引用 `veer-editor` 的 `VeerCore`（解析、AI 编辑、校验、控制器）和 `VeerUI`（设计系统）。Editor 继续作为独立产品 |
| 许可证 | 保留所有权利，仓库私有 | Mihomo（GPL-3.0）只作为独立程序随应用附带，不链接进 Veer；附带它的许可证和对应源码信息 |
| 参考项目 | FlClash、Bettbox（都是 GPL-3.0，Flutter + Dart） | 只参考功能和交互设计，不复制代码 |

## 参考项目的做法（macOS）

| 功能 | FlClash / Bettbox | Veer |
|---|---|---|
| 内核 | Mihomo 编译进应用或作为子进程，通过 FFI 或 IPC 控制 | 附带的 `mihomo` 作为子进程运行，通过 external-controller（只监听本机、随机端口、随机密钥）控制 |
| 系统代理 | `networksetup` 设置每个网络服务的 HTTP、HTTPS、SOCKS 代理 | 相同；退出或崩溃恢复时清除 |
| TUN | 用 `osascript` 管理员授权，把内核改成 setuid root（FlClash 用 `chmod 4750`） | 用 `SMAppService.daemon` 注册一个由用户在系统设置里批准的后台服务，由它以 root 身份运行内核。不修改任何文件权限。需要 Developer ID 签名，放在第 3 阶段 |
| 界面 | Flutter，概览、代理、配置、连接、日志、工具 | SwiftUI 原生：菜单栏 + 主窗口侧栏，沿用 Editor 的设计系统 |
| 特色 | 覆写脚本、WebDAV 备份、托盘、全局快捷键（FlClash）；DNS 调试工具箱、小组件、智能启停（Bettbox） | AI 分流、最近连接 → 规则、配置体检；其余按阶段评估 |

## 架构

```text
veer/macos/                  仓库 SpectreAX/veer 的 macOS 子目录
├── Package.swift            依赖 ../../veer-editor（VeerCore、VeerUI）和 Yams
├── Sources/
│   ├── VeerProxy/           代理引擎（无界面，可测试）
│   │   ├── CoreRunner       启动、停止和监视 mihomo 子进程
│   │   ├── RuntimeConfig    在配置文件之上写入 Veer 的端口、控制器和 TUN 设置
│   │   ├── SystemProxy      networksetup 封装，可以注入测试替身
│   │   └── ProfileStore     配置文件、订阅（链接保存在本机 0600 文件中）
│   └── VeerApp/             SwiftUI 应用：菜单栏、主窗口、设置
├── Tests/VeerProxyTests/
├── scripts/build-app.sh     打包 dist/Veer.app，附带 mihomo 和许可证
└── docs/
```

数据目录：`~/Library/Application Support/Veer/`，包含 `profiles/`、内核工作目录 `core/`（geodata 缓存、`runtime.yaml`）和 `state.json`。

运行时配置：Veer 在配置文件之上覆盖以下项目，其余字段原样保留。
- `mixed-port`：默认 7890，可在设置中修改。
- `external-controller`：`127.0.0.1` 加随机空闲端口。
- `secret`：每次启动随机生成。
- `allow-lan`：默认关闭。
- `tun`：第 3 阶段之前不启用。
- `external-ui`：移除。
- `log-level`：`info`。

## 阶段

### 第 1 阶段：可用的代理（本次）
1. 在 Editor 仓库中导出 `VeerCore` 和 `VeerUI` 两个库，Editor 本身的行为不变。
2. 搭建项目：Swift 包、应用外壳、打包脚本、附带的 mihomo、许可证。
3. 内核：启动、停止、崩溃检测并显示最后几行日志、退出时停止；等待控制器就绪。
4. 配置：从文件、链接或剪贴板导入（复用 `ConfigImporter`），更新订阅，切换当前配置。切换后用 `PUT /configs` 重新载入，不重启进程。
5. 代理组：列出策略组和节点，为选择型策略组切换节点，测试延迟。
6. 模式（规则、全局、直连）和系统代理开关。
7. 菜单栏：状态、实时速率、开关、模式、当前出口，以及打开主窗口。
8. 状态覆盖：未导入配置、内核启动中、运行中、启动失败（显示原因并可恢复）、端口被占用、订阅更新失败。

### 第 2 阶段：AI 分流
- 在 Editor 仓库中把 Editor 的界面拆成库（`VeerEditorUI`），嵌入 Veer 的“分流”页，作用于当前配置。
- 写入草稿后可以“立即生效”：内核支持 `PUT /rules`（MetaCubeX/mihomo#3373，尚未合并）时只替换规则，否则用 `PUT /configs`。Veer 自己运行内核，所以替换整个配置也是安全的。
- 最近连接、配置体检和查询工具直接作用于 Veer 自己的内核，不需要再填控制器地址。

### 第 3 阶段：TUN
- 用 `SMAppService.daemon` 注册后台服务，以 root 身份运行内核，通过 XPC 校验调用方的签名。
- 处理 DNS 劫持、恢复路由，以及服务需要批准、被拒绝、需要更新等状态。

### 第 4 阶段：完整度
连接与日志页、流量统计、覆写设置（DNS、规则附加）、开机启动、全局快捷键、自动更新（Sparkle）、备份与恢复、DMG 发布与公证。

## 不在计划内
- Mac App Store 版本（GPL 与 App Store 条款冲突，需要单独评估许可证）。
- 复制 FlClash、Bettbox 或 Doona 的代码。
- iOS 版本（之后共享 `VeerCore` 和 `VeerProxy` 的协议部分）。

## 验证
- **单元测试：** `RuntimeConfig`、`SystemProxy`（命令替身）、`ProfileStore`，以及 `CoreRunner` 用真实 mihomo 的启动和停止。
- **实机：** 启动内核，通过代理端口访问网站，切换节点，开关系统代理，退出后系统代理已清除。
- **截图：** 各状态的浅色和深色截图。
