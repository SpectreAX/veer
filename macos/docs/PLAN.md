## 启动性能（2026-11-16，Claude，问题 03）

**结论：** 慢的不是内核，是 Veer 启动内核之前准备配置的那几秒。内核本身 25–160 ms 就绪。

**测量方法：** 独立的基准程序调用 Veer 自己的 `VeerProxy`/`VeerCore`，在数据副本上跑（两份真实配置的副本，独立目录，随机端口，随包 Mihomo），
每个阶段用 `ContinuousClock` 计时，就绪用 2 ms 轮询。没有启动 Veer 应用，没有改系统代理或 TUN。每组 10 次（切换配置 5 次，Provider 场景各 3 次，冷 geodata 1 次）。

| 场景（到控制器就绪，ms） | 修改前 P50 / P95 | 修改后 P50 / P95 |
|---|---|---|
| 小配置（74 节点、9263 条规则、7 条“我的分流”修改），首次启动 | 3213 / 3236 | 1138 / 1212 |
| 大配置（247 节点、4110 条规则、1 个 provider） | 4457 / 4652 | 147 / 162 |
| 切换配置后启动（每次新进程），小 / 大 | 未测 | 1099 / 1107，139 / 152 |

修改后到“首次经代理的请求成功”：小配置 P50 1686 ms、P95 1951 ms（修改前 3727 / 4275）。大配置的副本没有带上节点选择记录，默认节点不通，这一项没有数据。

**各阶段（ms，P50，修改前 → 修改后）：** 小配置：应用“我的分流” 2843 → 882，生成运行配置 149 → 35，其余合计约 55 不变；
大配置：生成运行配置 4365 → 63，其余合计约 70 不变。进程创建 0.6，内核从启动到应答：小配置约 165，大配置约 22。

**原因与修改：**
- `ConfigImporter.readableUnicode` 每替换一个 `\U` 转义都从头重新定位，国旗 emoji 多的订阅是平方级：大配置每次启动、每次重载 4.3 秒。改为一次扫描。
- 重放“我的分流”时对每条规则单独做一次 YAML 解析，而 Yams 每次解析都读一遍整个进程环境变量（0.2 ms）：9263 条规则 × 7 条修改。默认编码改为只读一次。
- `ConfigDocument.parse` 和 `SourceLines` 用 Foundation 的字符串搜索找 Tab 和 CRLF，大文本每次 30 ms，每条修改约 5 次。改为按字节查。
- 运行配置里每条置顶规则各扫一遍全部规则行，改为一次放入。
- 就绪轮询 100 ms 一次且就绪后多问一次版本，改为前 2 秒 20 ms 一次，不再重复询问。

**新发现并已修：** Provider 链接慢或不通且没有缓存时，内核 30 ms 就应答并监听端口，但 10–16 秒内丢弃所有连接（先读节点列表再读规则集，不通的每个等 5 秒）。
原来 Veer 这时已显示运行中并打开系统代理，所有应用在这段时间断网。现在等内核真正承载流量（见 SPEC 4.3）。实测 Veer 的判定时刻与真实可用时刻：
8 秒慢链接 16.1 s / 16.7 s，不通 10.1 s / 10.3 s，有缓存 0.03 s / 0.3 s，两份真实配置在控制器就绪后 5–20 ms 内判定可用。冷 geodata（空目录、大配置，1 次）：下载 MMDB 0.77 s，控制器就绪 0.9 s。

**检查过、没有问题或没有改：** 没有固定 sleep 等内核；geodata 只在缺失时下载；启动不触发 provider 更新；测速、出口检测、服务检测都在就绪之后且不阻塞；
配置准备都在后台线程。策略组检查做了两次（合计 7–24 ms），保留：第一次要在 TUN 服务之前拦住坏配置。停止内核 25–50 ms。

**生效配置的磁盘缓存（同日追加）：** 带“我的分流”修改的配置原来在应用启动后的第一次启动还要约 0.9 秒重放修改。现在结果存在
`cache/effective/<id>.json`（仅用户可读，不进备份），键是配置文本、分流层文件和程序本身（大小与修改时间，每次构建和更新都变）的 SHA-256；
任何一项变了就重算，文件损坏或读写失败只是重算一次。没有分流层的配置不缓存。实测小配置（每次新进程，10 次）：应用“我的分流” 882 → 26 ms，
到控制器就绪 P50 260 ms、P95 264 ms（未命中 1 次：1219 ms），到首次经代理的请求成功 P50 770 ms、P95 857 ms。

- **状态：** `StateStore`，包括启动时恢复上次的代理状态。系统代理改为开启前保存快照、关闭时恢复。
- **首次使用引导**（SPEC 5.1）。
- **实机清单：**
  - 删掉数据目录后启动 Veer，走完引导，能访问网站；
  - 取消勾选一个节点，代理组里不再出现它；
  - 更新订阅后，勾选状态还在；
  - 导出的 YAML 能被 `mihomo -t` 校验通过；
  - 手动设置一个别的代理，再开关 Veer 的系统代理，原来的代理会恢复；
  - 切换语言并重启后，界面全部变成英文。

### 第 2 步：Agent
- **界面：** 对话列表、对话、输入框、执行模式、模型选择，以及第一次打开时的 AI 设置引导。
- **工具调用：**
  - 显示和展开；
  - “这次发送了什么”。
- **配置修改：**
  - 差异卡片 → 写入层 → `PUT /configs` 立即生效 → 撤销。
- **运行状态操作：**
  - 扩展 AI 输出结构；
  - 解析和执行，带撤销。
- **解释路由；** 连接、规则、节点行上的“问 AI”。
- **翻译 `VeerCore` 的报错和说明**（第 1 步只翻译了应用、代理引擎和设计系统里的文案）。
- **实机清单：**
  - 说“Netflix 走日本”，应用后访问 Netflix，在连接页里看到它走的是日本节点；
  - 撤销后恢复原样；
  - 说“ChatGPT 换到最快的美国节点”，节点切换完成，撤销后恢复；
  - 问“为什么 github.com 走了代理”，回答里的规则和连接页显示的一致；
  - 展开“这次发送了什么”，里面没有服务器地址和订阅链接。

### 第 3 步：连接、日志、覆写、DNS
- 连接页（SPEC 5.5，含“为这个域名添加规则”）、日志页（5.6）。
- **覆写：** `RuntimeConfig` 加入 IPv6、进程匹配、禁用 QUIC 和 DNS 默认值（SPEC 第 3 节）。设置里加上“代理”和“DNS”两页。
- **出口 IP 检测**（SPEC 5.2）。
- **实机清单：**
  - 关闭一个连接后，它从列表中消失；
  - 日志可以暂停、搜索；
  - 开启禁用 QUIC 后，访问 YouTube 改走 TCP（可以在连接页查看）；
  - 出口 IP 和所选节点的地区一致。

### 第 4 步：TUN 后台服务
- **签名：** 测试阶段用免费的 Apple Development 证书（本机已有）。开工后先验证 `SMAppService.daemon` 在这个签名下能不能注册和批准；不能的话，改用 SPEC 4.1.1 的手动安装方式，不必为了测试提前加入付费计划。
- **内容：**
  - `VeerHelper`：注册、批准状态、XPC 签名校验、以 root 运行内核、断开后清理；
  - `CoreRunner` 协议；
  - 失败时回退到系统代理；
  - 设置里加上“TUN”页。
- **打包：** `build-app.sh` 把后台服务和 plist 放进应用包，并用 Apple Development 证书签名；发布时换成 Developer ID。
- **实机清单：**
  - 第一次开启 TUN 时，提示去系统设置批准，批准后 TUN 生效；
  - 终端里 `curl` 不设代理也能通过 Veer；
  - 局域网和 Tailscale 地址不走 TUN；
  - 强制退出 Veer，10 秒后内核停止，网络恢复正常；
  - 拒绝批准时，Veer 回退到系统代理并说明原因；
  - 如果用的是手动安装：输入一次密码后安装成功；重新编译 Veer 后 TUN 仍然能用（Apple Development 签名）；卸载后 `/Library/LaunchDaemons/` 和 `/Library/PrivilegedHelperTools/` 里没有残留。

### 第 5 步：订阅增强
- 节点地区离线识别、手动标记、世界地图视图。

- 流量和到期提醒、内置规则模板（打包模板内容前，先确认 ACL4SSR 的许可证）。
- **实机清单：**

  - 地图上点击一个地区，列出的节点正确；
  - 把更新间隔改成 1 小时，到时会自动更新；
  - 剩余流量低于 10% 时收到一次通知。

### 第 7 步：Agent 侧边面板
规格见 [SPEC.md](SPEC.md) 6.1。

- **做法：**

- **开关动画（2026-11-15）：** 面板与正文由 `PanelRevealStack` 一个布局驱动，正文每帧得到真实宽度。动画途中不做结构性改动（面板提前建好、指针开关与换排在开始前完成、输入与焦点在停下后开启），网格和行的排法用 `SteadyGrid` / `SteadyChoice` 在动画开始前按较窄一端定好。待实机确认：真实窗口里开关的手感（含侧边栏、测速与 Agent 回复进行中、窗口缩放时）、macOS 14。
