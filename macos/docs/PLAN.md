# Veer for macOS：开发计划（2026-10-29）

本计划按 [REQUIREMENTS.md](REQUIREMENTS.md) 和 [SPEC.md](SPEC.md) 推进，取代 [PLAN_2026-10-29.md](PLAN_2026-10-29.md) 的第 2 到第 4 阶段。那份文档的第 1 阶段（可用的代理）已经完成并提交。

## 每一步怎样算完成
1. `swift test` 全部通过。新逻辑都要有单元测试。
2. `SnapshotRunner` 输出这一步涉及的每个页面和状态，浅色、深色、中文、英文各一张，逐张检查。
3. 在 macOS 26 实机上走完这一步的实机清单。涉及界面外观的步骤，还要在 macOS 14 虚拟机上走一遍。
4. 单独提交，提交信息说明这一步做了什么。

## 步骤

### 第 0 步：最低系统改为 macOS 14
- `Package.swift` 改为 `.macOS(.v14)`，`Info.plist` 改为 14.0。
- 只在 macOS 26 上存在的接口（目前只有 `.glassProminent`）用 `#available` 加上回退。
- **验收：** 编译通过，测试通过。

### 第 1 步：外壳、国际化、“我的分流”层、首次引导
- **界面外壳：**
  - 侧栏两组（代理、AI），连接、日志、Agent 先放占位页；
  - `VeerUI` 的 Glass 组件加上旧系统回退；
  - 菜单栏按 SPEC 第 7 节调整。
- **国际化：**
  - 中英文 `.strings`；
  - 键一致性测试、缺失键扫描脚本；
  - 设置里的语言切换。
- **“我的分流”层：**
  - `RoutingLayer`：存储、生效配置、重放、冲突、节点勾选；
  - 导出配置。
- **状态：** `StateStore`，包括启动时恢复上次的代理状态。系统代理改为开启前保存快照、关闭时恢复。
- **首次使用引导**（SPEC 5.1）。
- **实机清单：**
  - 删掉数据目录后启动 Veer，走完引导，能访问网站；
  - 取消勾选一个节点，代理组里不再出现它；
  - 更新订阅后，勾选状态还在；
  - 导出的 YAML 能被 `mihomo -t` 校验通过；
  - 手动设置一个别的代理，再开关 Veer 的系统代理，原来的代理会恢复；
  - 切换语言并重启后，界面全部变成英文。

### 第 2 步：Agent
- **界面：** 对话列表、对话、输入框、执行模式、模型选择，以及第一次打开时的 AI 设置引导。
- **工具调用：**
  - 显示和展开；
  - “这次发送了什么”。
- **配置修改：**
  - 差异卡片 → 写入层 → `PUT /configs` 立即生效 → 撤销。
- **运行状态操作：**
  - 扩展 AI 输出结构；
  - 解析和执行，带撤销。
- **解释路由；** 连接、规则、节点行上的“问 AI”。
- **实机清单：**
  - 说“Netflix 走日本”，应用后访问 Netflix，在连接页里看到它走的是日本节点；
  - 撤销后恢复原样；
  - 说“ChatGPT 换到最快的美国节点”，节点切换完成，撤销后恢复；
  - 问“为什么 github.com 走了代理”，回答里的规则和连接页显示的一致；
  - 展开“这次发送了什么”，里面没有服务器地址和订阅链接。

### 第 3 步：连接、日志、覆写、DNS
- 连接页（SPEC 5.5，含“为这个域名添加规则”）、日志页（5.6）。
- **覆写：** `RuntimeConfig` 加入 IPv6、进程匹配、禁用 QUIC 和 DNS 默认值（SPEC 第 3 节）。设置里加上“代理”和“DNS”两页。
- **出口 IP 检测**（SPEC 5.2）。
- **实机清单：**
  - 关闭一个连接后，它从列表中消失；
  - 日志可以暂停、搜索；
  - 开启禁用 QUIC 后，访问 YouTube 改走 TCP（可以在连接页查看）；
  - 出口 IP 和所选节点的地区一致。

### 第 4 步：TUN 后台服务
- **前提：** 需要 Developer ID Application 证书和 Team ID，开工前确认已经拿到。
- **内容：**
  - `VeerHelper`：注册、批准状态、XPC 签名校验、以 root 运行内核、断开后清理；
  - `CoreRunner` 协议；
  - 失败时回退到系统代理；
  - 设置里加上“TUN”页。
- **打包：** `build-app.sh` 把后台服务和 plist 放进应用包，并用 Developer ID 签名。
- **实机清单：**
  - 第一次开启 TUN 时，提示去系统设置批准，批准后 TUN 生效；
  - 终端里 `curl` 不设代理也能通过 Veer；
  - 局域网和 Tailscale 地址不走 TUN；
  - 强制退出 Veer，10 秒后内核停止，网络恢复正常；
  - 拒绝批准时，Veer 回退到系统代理并说明原因。

### 第 5 步：订阅增强
- 节点地区离线识别、手动标记、世界地图视图。
- 订阅自动更新（按 `profile-update-interval`，先直连、失败再走代理）。
- 流量和到期提醒、内置规则模板（打包模板内容前，先确认 ACL4SSR 的许可证）。
- **实机清单：**
  - 用你的真实订阅检查，90% 以上的节点能识别出地区；
  - 地图上点击一个地区，列出的节点正确；
  - 把更新间隔改成 1 小时，到时会自动更新；
  - 剩余流量低于 10% 时收到一次通知。

### 第 6 步：收尾与发布
- **功能：** 全局快捷键、开机启动、Sparkle、备份和恢复、诊断包、主动建议、请求页、DNS 页、路由地图、配置诊断。
- **发布：**
  - 新建公开仓库 `SpectreAX/veer-releases`；
  - DMG 打包、公证，appcast 用 EdDSA 签名；
  - “关于”页放上赞助链接（等你开通 GitHub Sponsors 和爱发电后填入）。
- **实机清单：**
  - 从上一个版本通过 Sparkle 升级到新版本；
  - 用备份恢复到一个新用户账户；
  - 全局快捷键在其他应用里也能用；
  - 公证后的 DMG 在另一台 Mac 上能直接打开，不弹出“无法验证”的提示。
